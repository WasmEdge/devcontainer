# Devcontainer for WasmEdge

This repository owns the Dockerfiles and GitHub Actions workflows used to
build and validate WasmEdge development and CI images.

## Layout

- `.devcontainer/` — editor-facing Dev Container configuration.
- `docker/` — CI and distributable image definitions and Docker Bake files.
- `scripts/` — installer scripts and patches copied into plugin
  dependency build contexts.
- `.github/workflows/` — image, static-library, and OpenWrt validation.

The Docker definitions were ported from the WasmEdge `0.18.1` release
(`b2e483553ea7a1826be117180125c71e5d0b8958`). Existing image tags remain
compatible with `wasmedge/wasmedge`, but publishing is disabled until registry
ownership and credentials are explicitly approved.

## Local validation

Run the repository checks from the root:

```bash
PYTHONPATH=scripts python3 -m unittest \
  scripts/test_check_docker_migration.py \
  scripts/test_docker_workflow.py
PYTHONPATH=scripts python3 scripts/check_docker_migration.py
```

With Docker Buildx installed, resolve each Bake file without building or
publishing:

```bash
for file in docker/docker-bake.*.hcl; do
  docker buildx bake -f "$file" --print
done
```

The static-library workflows download the pinned WasmEdge `0.18.1` source
archive into `WasmEdge-0.18.1/`, write its `VERSION` file, and run the
destination Bake file from the checked-out repository. The Bake definition
passes that extracted directory as the named `source` context.

The OpenWrt workflow builds an OpenWrt rootfs artifact and then uses
`docker/Dockerfile.openwrt` for the image smoke test. The OpenWrt runtime test
requires a disposable Linux runner with Docker privileged-container support.

## Bake definitions

| Bake file | Purpose | Platforms/targets |
|---|---|---|
| `docker-bake.ci-image-base.hcl` | CI host images | `linux/amd64`, `linux/arm64` |
| `docker-bake.alpine-base.hcl` | Alpine base image | `linux/amd64`, `linux/arm64` |
| `docker-bake.ubuntu.hcl` | Ubuntu build/plugin images | Ubuntu 20.04, 22.04, 24.04; x86_64 and aarch64 target |
| `docker-bake.manylinux.hcl` | manylinux build/plugin images | `linux/amd64`, `linux/arm64` |
| `docker-bake.alpine-static.hcl` | Alpine static WasmEdge archive | `linux/amd64`, `linux/arm64` |
| `docker-bake.debian-static.hcl` | Debian static WasmEdge archive | `linux/amd64`, `linux/arm64` |

Older platform Dockerfiles under `docker/` are retained for manual or legacy
use, including manylinux2014, Ubuntu 20.04 x86_64, Ubuntu 21.04 armv7l, and
the release image. The release image requires a supplied
`WasmEdge-$VERSION-Linux.tar.gz` in its build context; it is not generated by
this repository checkout.

## GitHub Actions

`.github/workflows/docker.yml` is the consolidated image workflow. It runs on
pull requests, pushes to `main`, schedules, and manual dispatch. Pull requests
and all current destination runs use `push: false`; no Docker Hub login is
performed. The expected future registry namespace is `wasmedge/wasmedge`, but
the destination repository must receive approved `DOCKER_USERNAME` and
`DOCKER_ACCESS_TOKEN` secrets and publication ownership before any push logic
is enabled.

Static workflows upload artifacts only. If `release` is set, they fail
explicitly because cross-repository release publication has not been approved.

## Validation status

The Python migration and workflow policy tests pass. Deterministic Dockerfile,
Bake path, context, and local-input checks pass. Docker Buildx and `actionlint`
were unavailable in the macOS implementation environment, so actual image
builds, Bake resolution, and OpenWrt privileged smoke tests remain CI-only
verification before publishing can be considered.
